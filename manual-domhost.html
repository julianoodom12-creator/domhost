Conectar sua conta GitHub

O DomHost publica seus sites através do GitHub Pages (grátis e ilimitado). Para isso, você conecta um token — só na primeira vez. Depois disso, fica salvo no seu navegador.

1
Acesse github.com e faça login na sua conta.
2
Clique na sua foto de perfil (canto superior direito) → Settings (Configurações).
3
Role até o final do menu esquerdo → Developer settings.
4
Clique em Personal access tokens → Tokens (classic).
5
Clique em Generate new token (classic). Dê um nome (ex: "DomHost") e em Expiration escolha No expiration (pra nunca expirar).
6
Em Select scopes, marque: ☑ repositório (repo) e ☑ delete_repo (excluir_repositório). As sub-opções do repo marcam sozinhas. Nenhuma outra permissão é necessária.
7
Clique em Generate token e copie o código ghp_... (ele aparece só uma vez!).
8
Abra o DomHost → Entrar → cole o token → Entrar →. Pronto! 🎉
💡 Dica: marque APENAS "repo" e "delete_repo". Quanto menos permissão, mais seguro. Ignore as opções de chave pública/SSH — não têm relação com o DomHost.
🔒 Segurança: o token fica salvo somente no localStorage do seu navegador, no seu computador. Nunca é enviado para nenhum servidor além do GitHub.
🚀

Fazer Deploy (publicar um site)

O coração do DomHost: arraste a pasta do seu site e ele vai pro ar em segundos, com HTTPS e CDN global.

1
Abra a página Deploy do DomHost (menu → 🚀 Novo Deploy).
2
Em Nome do projeto, digite o nome desejado (só letras, números e hífen). Ex: loja-maria → URL final: julianoodom12-creator.github.io/loja-maria
3
Arraste a pasta do seu site para a área pontilhada — ou clique nela para selecionar os arquivos. Subpastas como css/ e img/ são lidas e mantidas automaticamente.
4
Confira a lista: os arquivos aparecem com tamanho. O ideal é ter um index.html (a página inicial).
5
Clique em 🚀 Fazer Deploy e assista o terminal: cada arquivo aparece subindo em tempo real, com barra de progresso.
6
Quando aparecer 🎉 Site no ar!, clique em Abrir site ↗ ou copie a URL.
💡 Dica: cada arquivo pode ter até 25MB. O deploy cria automaticamente um repositório no seu GitHub e ativa o GitHub Pages — tudo sozinho.
⚠️ Importante: na primeira vez, o GitHub Pages leva de 1 a 2 minutos para construir o site. Se aparecer "404" logo após o deploy, aguarde um pouco e atualize a página (F5).
🔄

Atualizar um site já publicado

Editou os arquivos? Publicar a nova versão é simples — nem precisa deletar nada.

1
Edite os arquivos do site no seu computador (pasta do projeto).
2
Abra o DomHost → 🚀 Novo Deploy.
3
Digite o mesmo nome do projeto (ex: meu-site). O DomHost detecta que o repositório já existe.
4
Arraste a pasta completa atualizada (todos os arquivos, não só o que mudou).
5
Fazer Deploy → os arquivos antigos são substituídos. Site atualizado em ~1 minuto.
💡 Dica: sempre arraste a pasta COMPLETA do site, com todos os arquivos — assim nada fica faltando na nova versão.

Domínio Grátis (is-a.dev) — NOVO!

Troque o endereço longo do GitHub por um nome profissional, sem configurar DNS e sem pagar nada.

Como funciona:

O DomHost automatiza o registro no is-a.dev, um serviço que dá subdomínios grátis para desenvolvedores. Você escolhe o nome, e nós criamos o pedido (Pull Request) no repositório oficial deles automaticamente.

1
No dashboard, clique em 🎁 Domínio Grátis.
2
Escolha o projeto que vai receber o domínio (tem que estar publicado).
3
Digite o nome do subdomínio (3-20 caracteres). Ex: domhost → vira domhost.is-a.dev
4
Digite seu email (obrigatório no registro).
5
Clique em 🎁 Criar pedido automático. O DomHost faz sozinho: fork do repositório oficial → cria o arquivo de registro → abre o Pull Request pronto.
6
Acompanhe o PR pela seção Meus pedidos (botão "Ver PR ↗").
⏱️ Prazo: os mantenedores do is-a.dev aprovam em 1 a 7 dias. Aprovado = domínio no ar com HTTPS, sem você mexer em DNS nenhum.
⚠️ Requisito: o site precisa estar no ar com conteúdo real. Sites vazios, em construção ou redirecionamentos são rejeitados.
💡 Exemplos de nomes: meuportfolio.is-a.dev, lojamaria.is-a.dev, appclima.is-a.dev — profissional e grátis!
🌐

Conectar Domínio Próprio (comprado)

Comprou um domínio (.com, .com.br...)? Use ele no seu site em vez do endereço do GitHub.

1
No dashboard, clique em 🌐 Conectar Domínio.
2
Escolha o projeto que vai receber o domínio (ex: meu-site).
3
Digite o domínio sem http:// — ex: meusite.com.br → clique Conectar.
4
Abra o painel da empresa onde comprou o domínio (Registro.br, GoDaddy, Hostinger...) e crie os registros DNS abaixo:
TipoNomeValor
A@185.199.108.153
A@185.199.109.153
A@185.199.110.153
A@185.199.111.153
CNAMEwwwjulianoodom12-creator.github.io
5
Volte no DomHost e clique em Verificar agora — o status mostra se o DNS já propagou e se o HTTPS ativou.
⏱️ Atenção: a propagação do DNS leva de 10 minutos a 24 horas. O HTTPS liga sozinho depois que o DNS propaga.
💡 Subdomínios grátis: quantos quiser — app.seudominio.com, blog.seudominio.com — cada um apontando para um projeto diferente (via CNAME para julianoodom12-creator.github.io).
🗑️

Deletar um Projeto

Remove o site, o repositório GitHub e todos os arquivos — permanentemente.

1
No dashboard, localize o card do projeto.
2
Clique no botão 🗑 (vermelho, ao lado de GitHub).
3
Leia o aviso e confirme clicando em OK.
4
Digite o nome exato do projeto para confirmar (proteção contra clique acidental).
5
O card desvanece e o projeto é apagado. A lista atualiza sozinha.
⚠️ Cuidado: esta ação é irreversível! O site sai do ar e todos os arquivos são perdidos. Para guardar uma cópia, baixe antes pelo botão GitHub → Code → Download ZIP.
🔑 Permissão: para deletar, o token GitHub precisa da permissão delete_repo (veja seção 1).

Perguntas Frequentes

❓ É realmente grátis?

Sim! Tudo roda em GitHub Pages (hospedagem grátis para sempre) + domínios grátis do is-a.dev. Zero custo, zero servidor.

❓ Erro 404 depois do deploy

Normal na primeira vez. O GitHub Pages leva 1-2 minutos para construir. Aguarde e atualize com F5.

❓ "Bad credentials" ao entrar

Seu token expirou ou foi revogado. Crie um novo (seção 1) e cole novamente na página Entrar.

❓ O botão deletar não funciona

O token precisa da permissão delete_repo. Tokens antigos não podem ser editados — gere um novo com as duas permissões (repo + delete_repo).

❓ Não aparece a caixa de colar o token

Significa que você já está conectado nesse navegador! Para ver a caixa: F12 → Console → localStorage.removeItem('domhost_gh_token') → F5. Ou use uma janela anônima (Ctrl+Shift+N).

❓ Preciso saber programar?

Não! Se você tem uma pasta com um site (arquivos HTML), basta arrastar. O DomHost cuida de todo o resto.

❓ Consigo usar em vários computadores?

Sim! O DomHost é um site — acesse de qualquer lugar. Basta colar o token GitHub em cada navegador novo.

❓ Meu domínio is-a.dev foi rejeitado

Verifique se o site está no ar com conteúdo real (não vazio). Rejeitou mesmo assim? Escolha outro nome ou verifique no PR o motivo exato comentado pelos mantenedores.

📱 ERRO: "Failed to fetch" (conexão bloqueada)

O navegador bloqueou a rede — o site está certo, o problema é o ambiente. Siga nesta ordem:

1️⃣ Abra no Chrome direto — nunca dentro do WhatsApp/Instagram (o navegador interno de apps bloqueia a autenticação). Copie o link, abra o Chrome e cole.

2️⃣ Desative VPN e Economia de dados do navegador (⋮ → Configurações → Economia de dados → desativar). Não use Opera Mini.

3️⃣ Troque a rede — passe do Wi-Fi pro 4G (ou vice-versa).

4️⃣ Teste de 30s: abra api.github.com/zen no celular. Aparece frase = rede OK. Não carrega = problema na rede/VPN.

🗑️ O site não lembra o token / pede login toda hora

Você NÃO precisa mais limpar cache! O DomHost agora salva o token em dois lugares (localStorage + cookie de 1 ano) e se auto-recupera. Mas se ainda assim aparecer problema:

1️⃣ Abra login.html direto (ex: .../domhost/login.html) e cole o token de novo — isso resolve na maioria dos casos sem excluir histórico.

2️⃣ Só se não resolver: Chrome do celular → ⋮ → Histórico → Limpar dados → marque apenas "Cookies e dados de sites" (não precisa apagar tudo).

3️⃣ Volte no login.html, cole o token, entre. Pronto!

🔗 Erro 404 no site novo depois do deploy

Não entre em pânico — seu site está hospedado! O 404 é só o atraso da primeira construção do GitHub Pages (1-2 min). O que fazer:

1️⃣ Copie o link do site que aparece na tela de sucesso do deploy.

2️⃣ Abra em OUTRA página/aba e cole o link — espere 1-2 minutos e atualize (F5). O site estará funcionando, hospedado gratuitamente pelo DomHost.

3️⃣ Se após 10 minutos ainda der 404: confira no GitHub (botão "GitHub" no dashboard) se os arquivos subiram na branch main e se o Pages está ativo em Settings → Pages.

💡 Dica: na tela de sucesso, o botão "Abrir site ↗" já faz isso — copie a URL e compartilhe quando estiver no ar.
